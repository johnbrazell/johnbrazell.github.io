Procedural generation & adaptive pacing

A generated route needs variation in traversal difficulty, while the events during a run need to respond to what players are doing. I developed both systems around a designer-authored pacing curve.

In our CoG demonstration, the curve sets trail difficulty before play and provides the runtime target for event selection and storm pressure. Progress along the trail gives each system a common reference.

Trail difficulty and local overrides

Curve samples select difficulty profiles that control slope, elevation, and curvature. Connected trail segments then constrain the surrounding terrain. A river crossing can replace a difficult slope with flatter terrain: the water already adds a coordination challenge.

Generating a shared level across different hardware

Hardware-dependent generation originally led me to distribute terrain from the host. I quantized height values, compressed the image, and split the transfer into chunks for clients to reassemble.

The pipeline now combines CPU base noise with GPU terrain shaping and a canonical 16-bit height representation. Peers normally generate locally from the same resolved inputs. The height-image transfer remains available as a fallback; clients still build their local terrain and environment from that data.

Cross-hardware checks have produced closely matching playable terrain. Gameplay objects use host-authoritative placement, while locally generated environmental details can vary.

The director combines four normalized game-state inputs into an observed stress proxy.

Team progress selects the point on the target curve used for comparison; it is not another weighted input.

Event selection filters eligible events by cooldown and estimated effect. Storm speed provides a continuous adjustment between events.

Below target
Add pressure through a suitable encounter or a faster storm.
Above target
Prefer a relief event or slow the storm to give players recovery time.

Multiplayer interactions & local visuals

Tools and other objects move between the ground, a player’s hand, inventory, and the wagon. I built the authority and state handling for those transitions, along with the local visuals that show them.

Held-item response

The earlier held-item presentation lagged behind camera movement. I introduced a local visual proxy that follows the player’s view directly while the host continues to resolve shared gameplay state.

This separates the immediate visual response from the network updates used for the shared object. The comparison shows the original behavior on the left and the local proxy on the right.

Host authority and joining state

The host assigns unique object IDs and handles pickup, drop, inventory, and use requests. Session-aware snapshots reconstruct the world and held-item relationships for joining players. Acknowledgments and session tokens help distinguish current state from messages from an older connection.

World interest and navigation

Spatial dormancy and per-peer visibility focus synchronization on relevant objects, with interaction wakeups and cleanup behind the storm. Animal navigation uses corridor chunks around the wagon. Terrain render chunks provide another way to limit work to the area needed during play.

Animation synchronization

Movement blends, interaction selections, and action-speed parameters drive animation graphs locally on each peer. I also iterated on wagon-item clipping and added a timed escape action so a carried player can regain control.

Development tools & telemetry

Terrain preview and profiles

I built an editor preview for inspecting trail and terrain changes before starting a full session. Environmental scatter is omitted to keep previews faster and easier to inspect.

Editable generation presets resolve into stable session inputs. Separate seed domains keep unrelated random choices from shifting when another part of generation changes.

The generation clip and difficulty figure above show how trail structure and profile choices affect the terrain.

Run summaries and telemetry logs

I record the target curve, computed stress proxy, events, storm adjustments, and progress during a run. Those logs support the research analysis and help trace how the director responded to game state.

The post-game summary brings the route, pacing trace, and event markers together. I can inspect where the run diverged from the target and relate it to an encounter or location along the trail.

Pacing research

With Justus Robertson, Rochester Institute of Technology

Preliminary evaluation

The CoG paper reports ten developer sessions with generation, events, and storm control enabled. The analysis compared the computed stress proxy with the target throughout each session.

Mean absolute error
0.09
Session range
0.05–0.13
Standard deviation
0.03

These results describe target tracking by the combined system. Separate component tests and player-reported tension are planned follow-up work.

Research direction · Early exploration

Intent-guided playable world authoring

I’m exploring how natural-language requests and direct controls could guide the creation of playable worlds. The question is how to keep design intent editable while preserving authored regions and gameplay constraints through regeneration.

This proposed workflow builds on my existing generation and pacing systems. LLM integration and constraint-preserving editing are planned extensions.
