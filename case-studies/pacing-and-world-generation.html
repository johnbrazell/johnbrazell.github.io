Pull It Together / Case study 01

Shaping the journey,
before and during play.

Connecting procedural worlds, adaptive pacing, and tools for design iteration.

My role: system design & implementationGodot · C# · GDScriptCoG demonstration · August 2026

The design problem

A cooperative survival run needs room to build pressure and recover. A generated trail sets part of that rhythm, but players also change it through resource use, teamwork, and their response to encounters.

I designed and implemented systems that connect those layers. In the August 30, 2026 CoG demonstration, a shared target curve guided procedural generation and runtime control. My contribution spans the generation pipeline, pacing director, preview tools, and telemetry used to inspect a run.

Design decision

A pacing target, with room for gameplay.

The research build samples a target across progress to the goal and maps it to difficulty profiles. These profiles shape elevation, slope, and curvature along connected trail segments. The surrounding terrain blends around the trail and gameplay areas.

A river crossing is a useful tradeoff: water introduces its own challenge, so a modifier can lower the local trail difficulty. The authored target provides structure while traversal needs influence the actual space.

Coarse structure, continuous feedback.

During play, the director compares its target with a computed stress proxy: a game-state signal based on players, wagon condition, storm proximity, and environmental pressure. It uses that difference to select eligible pressure or relief events, while storm adjustments provide correction between encounters.

Illustrative decision from the presentation

Target 0.40 · Proxy 0.55

The proxy is 0.15 above target. Prefer an eligible relief event, such as Northern Lights, rather than adding another challenge.

The proxy gives the controller something actionable to observe. Players still determine how encounters unfold, and the signal describes game state rather than directly measuring their feelings.

Reproducible inputs, explicit authority.

Editable generation presets resolve into read-only session inputs. Separate random-seed domains isolate generation responsibilities. Clients normally generate locally from host-resolved inputs; a terrain-download fallback supplies the host height data when needed.

The terrain pipeline combines CPU base noise with GPU shaping, then uses a canonical 16-bit height representation for mesh and collision. Gameplay scatter is host-authoritative. Local environmental appearance uses stable candidate seeds, while placement can vary across hardware. Candidate-based appearance stays stable when other candidates are removed, without requiring every peer to place all environmental objects identically.

Tools that make a run inspectable.

I built terrain and level previews for checking generated layouts, with scatter omitted for faster visual iteration. Post-game maps, event histories, and pacing plots provide a second view: what the systems did during a completed run.

The shared-target behavior shown here is the CoG demonstration. The current development branch temporarily uses linear trail difficulty for debugging. Preview tool annotations are temporarily disabled around a Godot C# engine issue.
